# 小红书 AI 生图交付

外部流程：读取账号资产与任务 → 人物换装 → 场景参考图筛选与人工确认 → 场景图人物替换 → 成品交付。车辆检查与局部修复是“场景图人物替换”的内部必做工作，不新增对外审批步骤。

## 执行前

- 所有生成、AI换装与AI人物替换均在 Neowow 完成；不要静默切换生图服务。同机位实拍的确定性局部回贴使用随包脚本或现有专业编辑工具。新环境先读 [操作与费用](references/neowow-operation.md)，确认可用的浏览器控制能力与用户已登录的 Neowow。
- 固定资产由使用者按账号提供：人物身份基准（确认版正脸／三视图）、账号人设与风格、绑定车型配置及正确细节参考。人物与账号绑定，场景与人物分开；日常任务不重生三视图、不因换装重定义身份。缺少资产先补齐，除非另获授权，不创建新人物。
- 本次输入：账号、数量／用途／比例、服装与配饰要求、场景要求、图库入口、可复用画布、审核人、期限与生成预算。复用已有要求和审核记录；只澄清影响执行的缺项。图库入口未提供时，继续不依赖图库的准备工作。
- 账号图片、客户资料和画布入口仅保存在任务约定位置，不写进公共 Skill，不上传到无关服务；不索取或记录密码、Cookie、Token。提供素材不代表授权其他发布用途。
- 开始消耗积分前，说明操作范围、张数、页面显示的预计积分、重试上限并取得授权。已明确授权的批次在范围内继续，不重复询问；额度不足、范围变化或达到停止条件时停止追加。

## 1. 人物换装

1. 读取账号绑定的人物原始基准和本次服装。服装参考只提供穿搭，不提供人物身份；去除相互冲突的旧服装、饰品约束。
2. 缺少可判断效果的服装参考时，先提供可视搭配候选，让人确认。不得从场景图人物的穿搭自行推定目标服装。
3. 在 Neowow 新增换装版本，只调整本次服装及指定配饰，保持身份、体型、发型等未授权改动项。无需为了换装重新制作正侧背三视图。
4. 对照原始人物检查脸型五官、服装衣鞋、配饰与畸变，确认合格后提交人工确认。已确认且完全符合本次要求的换装结果直接复用。

产出：本次任务确认的换装人物参考；保留账号原始身份基准。场景替换时身份仍以原始基准检查，避免多次生成逐渐漂移。

## 2. 场景参考图筛选与人工确认

读取 [场景筛选标准](references/scene-selection.md)。Agent 自行进入用户指定图库，用缩略图粗筛、原图精查，处理分页／懒加载。按本次数量推荐足够且不过量的候选，不把整个图库交给人重新筛选。

每张推荐图必须实际打开查看，并附候选编号、预览、可重新定位的素材位置、车型核验依据、推荐理由与必要风险。车型／配置不明的图标记待核实，不能当作“OK”推荐。记录实际覆盖的图库范围；未看完不声称全库筛选完毕。

由人明确确认采用的候选。没有合格图时说明缺口并请求补素材，不凑数。换装与选景可以分别准备；二者都确认后才能生成场景图。多套穿搭／多场景时，明确每张成品采用的账号、穿搭版本和候选图对应关系。

## 3. 场景图人物替换（含内部修复）

### 配置与生成

1. 每张采用的场景图建立独立生成节点，保留原图与旧版本。场景原图提供构图、姿态、裁切、车辆、环境及光线；换装人物图提供本次身份与造型。必要时另附原始正脸强化身份，但先核实当前工具的参考图能力和编号。
2. 按真实引用顺序适配 [提示词骨架](references/neowow-operation.md#提示词骨架)。去掉重复引用；核对缩略图、编号和参数。车内图保留原自拍裁切，不为展示全身服装扩大画面；只输出单张照片，不输出拼图或资料板。
3. 切换节点后返回回读提示词、引用与参数；在授权预算内生成。以实际结果加载为完成依据，受理回执不算成图。先完成代表性小样并初检，再在已授权范围内继续。

### 内部检查与局部修复——每张必做

对照人物原始基准、已确认穿搭和场景原图，逐张放大检查：

- 同一人物可辨认，无明显五官漂移；手、肢体、服装、配饰与任务一致。
- 无悬浮、穿帮、异常遮挡；受光、接触阴影、肤色和清晰度与现场相符。
- 绑定车型与配置准确；可见轮毂结构、中心标、轮胎文字、卡钳标识、灯组、车身标志及内饰与正确原图一致。不可见项记录为不可见，不虚构“已核验”。

发现车辆细节漂移必须修复。读 [局部修复](references/local-repair.md)，优先用同机位正确实拍进行对齐、遮罩回贴和边缘融合，保护人物及其他正确区域。修复后核对结构、标识、过渡和修复区域外像素；不得用生成文字或猜画 Logo 冒充实物准确性。检查后无需修改时记录“核验通过，无需修复”，不做无意义像素改动。

修复由 Agent 在本环节完成，外部使用者直接收到修复成品。内部保留输入、遮罩／变换、前后版本和检查结果，不要求使用者逐项确认技术操作。素材不足、角度差异过大、遮挡复杂或预算超限时停止该图并报告具体阻塞；未达标图不能交为合格成品。

先修绑定错误和配置错误，不默认整图重抽。同类失败连续发生且输入已检查仍无改善时暂停，提出换底图、局部修复或设计师介入方案；遵守本轮已约定的重试上限。

## 4. 保存与交付

- 按账号、场景、版本和状态命名。保留原资产、失败版本和已确认版本；本地修复成品上传回指定画布／交付位置，不能只留临时预览或空节点。
- 重新打开画布，确认最终图仍可加载；导出并重新打开成品，核对数量、尺寸、清晰度、图序及采用版本对应关系。
- 交付成品图片、可定位的版本位置和必要未解决项。内部制作记录复用任务现有载体，记录引用、参数、已确认选择、修复情况和费用证据，不额外搭一套工作台。
- 区分“已提交生成”“已保存”“内部初检通过”“业务审核通过”。仅有预算或单次报价时不能称实际扣费；账户总余额变化不能直接归因给本任务。
- 反馈先定位换装、选景、身份、融合或车型问题，再定向修改。确认后换风格／换服装属于需求变更；模糊审美意见先求具体参照，不能每条反馈都触发付费重抽。
- 本 Skill 截至图片制作与送审。发布文案、飞书写回、账号发布等按本次明确授权另行执行，不从制作授权推定发布授权。

验收：选景与穿搭有人工确认；身份与车型准确；可见错误已修复；正式文件和画布已核验；版本、费用证据与审核状态可区分。离线校验通过不代表某个新账号的在线生产已验证。
